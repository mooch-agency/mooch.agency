§ 01What it does

Same answer, 71% shorter.

Say Less is an output style for Claude Code. It changes how much Claude writes, not what it knows: reasoning, tool use, and coding behaviour are unchanged, only the reply gets shorter. Outcome first, one reason, the rest on request.

Use this when you're skimming past everything Claude writes to find the one line that matters
so that you can read the whole reply instead, and stop missing things in it

§ 03Before / after

Real output, same prompt, same model. The only difference between the two columns is the style.

Default · 98 words

The problem is DATE(created_at), wrapping a column in a function prevents the database from using an index on created_at.

Fix: use a range instead

SELECT * FROM events
WHERE created_at >= '2026-07-01'
  AND created_at <  '2026-07-02';

This is sargable, the index on created_at can be used directly.

Why it's faster:

  • Original: evaluates DATE() on every row (full table scan even with an index)
  • Fixed: the optimiser can do an index range scan and skip irrelevant rows entirely

Also make sure you have the index:

CREATE INDEX idx_events_created_at ON events (created_at);

If you're selecting all columns (SELECT *) on 10M rows, also consider whether you need all columns, projecting only the columns you need reduces I/O significantly, especially if the table is wide.

Say Less · 41 words

DATE(created_at) wraps the column in a function, making any index on created_at unusable. Use a range instead:

SELECT * FROM events
WHERE created_at >= '2026-07-01' AND created_at < '2026-07-02';

Then ensure you have an index on created_at. Also drop the * and select only the columns you need, returning 10M-row-wide results is expensive regardless of the scan.

Same findings, 58% less to read. That gap holds across the board: shorter on 10/10 benchmark prompts, by 61% to 80%.

§ 05How it's built

Examples set the length, not rules: the style file's own examples are the target the model matches, not a list of instructions it follows. One soft length bound is load-bearing, remove it and replies creep back up.

Every number on this page comes from a hermetic benchmark: no personal CLAUDE.md, settings, or plugin reaches either arm, so the style is the only variable. Counted in code, never by a model. Full method and results: benchmark/RESEARCH.md.
