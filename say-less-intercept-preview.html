> How do I undo my last Git commit?

Great question! Undoing your last Git commit is a really common thing to need, and thankfully Git gives you several different ways to do it depending on exactly what you want to happen to your changes.

The first and most common approach is to use git reset --soft HEAD~1. What this does is move your branch pointer back by one commit, while leaving all of the changes from that commit sitting in your staging area. This is usually what you want if you just committed too early, or you wrote a bad commit message, or you forgot to include a file.

If you would rather have the changes in your working directory but not staged, you can use git reset --mixed HEAD~1 instead, which is also the default behaviour if you do not pass a flag at all.

Finally, if you genuinely want the changes gone completely, there is git reset --hard HEAD~1, but please be careful with this one, because the changes really are discarded and recovering them is difficult.

One important caveat: if you have already pushed the commit to a shared remote branch, rewriting history with reset can cause problems for your teammates. In that case, the safer option is git revert HEAD, which creates a brand new commit that undoes the changes from the previous one, leaving the original history intact.
